# 0.7.0 — optional bounded Character and default-token batches

The converter and schema-v1 payload format retain v0.6.2 behavior. The optional batch companion reuses the existing managed lifecycle and verifier to process up to five creatures from one GM-only Handout. Images are uploaded through Roll20, then registered once by named GM-layer bulk selection or a private URL manifest. Preview reports conflicts/missing references; apply creates source Handouts, Characters, avatars and reusable defaults without per-Character token selection. Persistent job identities make unchanged retries audit the original objects after restart.

The core recognizes explicit comma-or attack alternatives before its remaining-comma ambiguity guard, preserving complete secondary/primary natural routines. Smite and bardic-music attack/damage terms honor their existing enable flags, including critical confirmation and extra damage. Existing signed actions still dispatch; older Characters need explicit managed preview/update to adopt newly constructed macros. No automatic old-Character migration or state-version change occurs.

Clean-first-import live acceptance passed for two approved real creatures in a disposable game on 2026-10-29, without post-import repairs. Actual attacks, damage, critical handling, spell references, independent modifier flags, avatars and dragged defaults were checked. Restart/retry preserved IDs and performed no unnecessary object writes. Private sources/images/game identifiers and test evidence are excluded from public release contents.

Install the core once and optionally the separate batch script below it. Preserve managed state and staging token identities. No batch upload/enumeration service, Journal organization, token renderer, campaign inventory integration or new AI service is included. Token Builder/inventory work remains separate local work.

Limits: 5 items, 200,000 input characters, 20 registrations per command, 1,000 image keys and 20 retained jobs. Ambiguity/partial output needs review. NPC summaries show three weapons; additional generated actions remain available. Spell effects, resources and modifier eligibility are GM-controlled; Smite remains a shared melee/ranged flag. Unsupported custom formulas fail closed. Built-in stored-object verification does not independently certify every live sheet calculation.

Release candidates require the existing staged/readiness checks, 30 smoke fixtures, campaign regressions, 129 lifecycle scenarios, and 14 batch scenarios. Windows PowerShell 5.1 is the shipping runtime; Node.js is for developer tests. All 696 Moonpile spell macros remain unchanged and bundled with permission; full SRD OGL 1.0a/Section 15 notices and the game-content designation are supplied separately from the original MIT software license. Seven fixture rule-text passages were replaced with original synthetic regression notes while preserving their upper mechanics and entry structure.
