# 0.6.2 — numeric attack output

Live Ochre Jelly roll tooltips showed unresolved Character-ID-qualified attribute references instead of numeric modifiers. Prior arithmetic tests substituted those references locally, masking the live-output defect. The dispatcher now substitutes each supported live arithmetic component before sending roll templates to chat. Zero terms disappear; nonzero components retain labels; negative modifiers use subtraction. A representative Jelly attack contains `1d20cs>20 + 4[BAB] + 2[Strength] - 1[Size]`, and damage contains `2d4[Dmg] + 3[Strength damage]`. Acid remains a separate note, as in the original importer.

Values are reread on every click, so later enabled buffs and penalties still work. The Character ID remains an internal dispatch target, outside the actual roll expressions. Existing verified Abilities need no regeneration: replace the installed script and click the same action. No reimport, Character update or Ability-ID change is needed.

Supported modifier values are numeric arithmetic, parentheses, unary signs, `floor`, `ceil`, `round`, `abs`, and bounded local numeric attribute references. Weapon dice remain dice. Unsupported modifier formulas (queries, dice-valued modifiers, cross-Character or cyclic references, invalid arithmetic) stop the action with an explicit error before any routine rolls are sent. Set the named modifier to a numeric value or supported arithmetic before retrying. They are not silently omitted or left unresolved for chat to misinterpret. Other routine-count and wielding-style limitations from 0.6.0 still apply; absent-ability handling from 0.6.1 remains unchanged.

Regression tests require actual dispatched output to contain neither unresolved attribute references nor Character IDs. The corpus runner clicks every generated attack Ability after importing/updating each payload, checking every message of multipart routines. Arithmetic tests still compare numeric results against source bonuses, damage and criticals and unfiltered templates, and now include the live Ochre Jelly case. Unsupported formulas must emit no attack message and an actionable error. Full regression/readiness and isolated staged-release checks remain required before pushing.

Live acceptance: after replacing the script, click the existing Jelly's Slam action, inspect its tooltip for labeled numeric modifiers and +5 total attack bonus, confirm 2d4+3 base damage, then enable a numeric buff and click again. Real Roll20 roll rendering and math still require this post-install check. No merge or release tag is authorized by automated tests alone.
