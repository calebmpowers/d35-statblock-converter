# 0.6.1 — absent-ability readback compatibility

Live commissioning of Ochre Jelly with 0.6.0 exposed one stored-object mismatch: PC `int.current` became `10` while the planned score, `int-base`, and NPC `npcint` remained empty, with both modifiers `0`. All other checks passed, including recalc consumption, avatar rendition normalization, selected-token binding, saved default token and visibility. This is a sheet representation issue for an absent score; it does not give Ochre Jelly Intelligence 10.

The importer now accepts blank or numeric/string 10 only for an absent PC ability total, corroborated by a single matching base-score Attribute, NPC-score Attribute and both modifier Attributes. The plan must specify an empty PC total, empty base and NPC scores, and zero modifiers, and those companion objects must contain exactly those values. Object IDs, existence/duplicates, maxima, numeric source scores, unrelated fields and all other values remain checked normally. A changed total such as 11 still blocks audit/update. An unmodified update does not repeatedly clear the sheet's placeholder or trigger recalc.

Newly converted imports and updates retain explicit absent-ability labels in Other (including older JSON with `Int ,`). The NPC score stays blank. The PC total can display 10 as a placeholder; use the NPC entry and non-score note as the rules meaning. This does not verify the live sheet's calculations or make ability checks valid for an ability the creature lacks.

## Recover the existing pending Character

Replace the installed importer with 0.6.1, then run:

```text
!d35import audit -P4t5QhdR_lq_vP54Fg8
!d35import report
```

Audit reads the pending import and verifies every stored object. It writes no Character, Attribute, Ability or token objects. If the corroborated placeholder is still the only discrepancy, it completes the pending import in place, retaining Character/Ability/Attribute IDs. If anything else differs, it continues to report failure. No reimport, adoption, force flag, or state editing is needed.

After recovery, ordinary preview/update against the existing source handout adds the explanatory Other note through the normal conflict-protected path:

```text
!d35import preview -P4t5QhdR_lq_vP54Fg8 -P4t51zQI_7cfzA9Sh4b
!d35import update -P4t5QhdR_lq_vP54Fg8 -P4t51zQI_7cfzA9Sh4b
```

Regression coverage models the observed representation for all six abilities, legacy blank-Int pending recovery, zero-write unchanged updates, later manual conflicts, companion/duplicate/missing/max guards and ordinary numeric values. The combined corpus passed all 67 imports/updates and all 125 lifecycle scenarios. The complete regression/readiness and isolated staged-release suites are release gates. Accepted placeholders are identified explicitly in JSON checks by `representation: corroborated-absent-ability-placeholder`, retaining both raw expected and observed values. Real post-install audit and rolls are still pending live acceptance. The no-spell warning is expected for Ochre Jelly and did not cause the failed import.
