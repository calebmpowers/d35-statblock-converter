# 0.6.0 — routine import usability, pending live acceptance

Convert DOCX (or TXT) to schema-version-1 JSON, paste it into a uniquely named Roll20 handout's GM Notes, select one unbound image token, and type `!D35 Handout Name`. Creation configures the sheet, avatar, token association, HP/AC bars, established visibility, reusable default token, and token actions, then reads stored objects back. No extra flags are required. Explicit advanced commands remain available.

Bio and NPC Description now contain only the canonical source reference, or stay empty when none exists. Managed updates correct previously owned text without recreating Characters; manual edits still conflict. Unclassified legacy notes remain in Other, and mechanical mappings remain intact.

Attack Abilities dispatch through the installed importer and its verified manifest. Each click removes currently zero/inactive arithmetic modifiers and retains labeled nonzero components. Conditional bonuses enabled later are read afresh. Existing action keys retain Ability IDs during updates. Ranged actions omit melee flank and higher-ground terms. Critical multipliers, iterative attacks, natural-attack counts, and source-specific routine bonuses remain intact.

This release also incorporates the recovered local parser/regression work present before this final pass: wrapped attack lines, compound natural iteratives, conditional AC/statistics preservation, explicit spell resistance, per-spell SLA caster levels, and lower at-will SLA references. Canonical campaign documents and production Drive artifacts are not changed.

## Automated verification

- Complete `tests/Run-Tests.ps1` and `tools/Test-ReleaseReadiness.ps1`, including TXT/DOCX conversion, Spell Reference, mappings, managed update/readback, token visibility and transient recalc coverage.
- 30 main conversion payloads plus two focused behavior fixtures; 37 saved local payloads validate separately.
- Shared-corpus import and update of all 67 main/saved payloads, with 110 isolated lifecycle/fault/usability scenarios.
- Arithmetic tests compare emitted compact rolls against both source bonuses/damage and unfiltered templates, using minimum and maximum dice. Cases cover melee/ranged, enhancement, threats/multipliers, natural repeats, five iteratives across multiple chat messages, later buffs/penalties, and disabled conditions. Additional cases exercise unsupported/recursive formulas and migration from literal macro Abilities while retaining IDs.
- The exact staged source tree is exported independently and runs the complete release-readiness gate with no recovery directories or saved local payloads. Importer mirrors must match.

## Routine-use limits

Keep the Mod installed: dispatched actions need its verified managed manifest. Unsupported expressions (including dice and queries) remain for Roll20 to resolve; cyclic or invalid sheet formulas can still fail there. The arithmetic parser does not execute JavaScript. Attack-count-changing conditions such as newly enabled haste/Rapid Shot/flurry need an authored routine or configured sheet controls; a numeric toggle alone does not add attacks. Manufactured-weapon Power Attack damage depends on wielding style absent from schema v1; configure the appropriate global damage modifier for that routine rather than assuming it is inferred. Other weapon-specific conditional effects need appropriate sheet configuration.

The app's retained legacy Inline command output targets older `!dnd35import B64:` tooling and is not accepted by the bundled managed importer. Use Handout JSON for the supported production workflow.

The 67-Character shared mock corpus used 4,275,204 UTF-8 bytes of importer state (4,275,069 UTF-16 code units), averaging about 63.8 KB per Character including the latest report. The largest manifest was 174,407 bytes; the latest report was 223,515 bytes. Same-mix linear projections are about 6.27 MB at 100 Characters and 12.32 MB at 200. These are measurements/projections, not verified Roll20 capacity. Pending operations duplicate candidate/ownership data and can grow state further. Operations are bounded to 5,000 journal entries and 10-second reads with a 30-second lifecycle timeout. Large campaigns and large creatures need live sandbox/storage checks; no state migration or storage redesign is introduced.

## Remaining live acceptance

In a disposable copy of the actual game:

1. Install both the compatible sheet and 0.6.0 importer; import a converted caster with `!D35 Handout Name` and one selected token. Verify source-only Bio/Description, all rules, spells, portrait, bars and success report.
2. Drag out the saved default token; check image, association, full HP/AC, dimensions, visibility, and vision settings.
3. Roll melee, ranged, natural/full attacks and criticals. Enable and disable a buff/penalty after import and compare actual roll tooltips/results with source and expected conditions.
4. Damage HP, spend spells, add manual content and alter encounter-token state. Preview/update the same Character from revised JSON; verify IDs, expenditure/current HP, manual additions and encounter state survive. Audit after workers settle and after a sandbox restart.
5. Confirm invalid inputs fail safely, managed manual edits block updates, and saved-token visibility/recalc readback stays correct with real workers.

Automated storage simulations do not verify live sheet calculations, roll rendering, image acceptance or sandbox capacity. Do not merge to main or tag a final release until these checks pass.
